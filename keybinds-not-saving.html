Keybinds & settings not saving LIVE TRACKER

Status Aug 8 (pre-launch): confirmed bug in the beta and playtest builds, officially acknowledged by Team17 support — launch fix unknown. This is not your fault and mostly not fixable from your side; below is what's confirmed, the two workarounds with real evidence, and the retest promise.

What's confirmed broken

  • Keybinds reset when you re-enter the in-game menu. "You save it, go back in game, and it resets. Even deleting keybinds and getting back in game resets them back" — "Keybinds keep reseting" report thread. One tester pinned the trigger precisely: binds reset "when exiting and entering the ingame menu", not when switching tabs (early-testing feedback thread).
  • Team17 knows. Official support reply, June 2: "we've had the issue with keybinds not saving correctly reported to us already" (support thread).
  • Still present in the July playtest build: mouse-wheel rebinds wouldn't save on Jul 29.
  • Non-QWERTY keyboards (AZERTY etc.) have an extra layer: binds display as the wrong keys and fail to save (AZERTY thread).

What actually helps (evidence-backed only)

  1. Rebind from the main menu, before joining a server. The observed reset trigger is the in-game settings menu; beta players kept binds longer doing everything from the title screen. Close and reopen settings once to confirm it stuck.
  2. Check your config isn't read-only. The popular 60 Hz-unlock fix tells you to set GameUserSettings.ini to read-only — which then silently blocks every settings save. Its own author warns: rebind first, set read-only last (performance thread). If you applied that trick, untick read-only before blaming the game.
  3. Don't hunt for a keybinds file to edit. The config folder is %LOCALAPPDATA%\HLLVietnam\Saved\Config\Windows, but it only holds GameUserSettings.ini (graphics/refresh). Testers found keybinds live in a non-editable .sav file — "Game does not use the typical UE config structure" — so HLL1-era advice about editing binds in the ini does not apply here.
  4. Add your report to the Report a Problem forum — support is actively collecting cases.
