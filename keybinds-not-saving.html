Keybinds & settings not saving LIVE TRACKER

Status Aug 25: Patch 1.2 went live on Aug 21 and it did fix part of this — but not the part most people are hitting. Team17's own changelog lists "Settings not saving correctly", "Duplicate keybind warnings" and "Tactical Map keybinding issues" among 500+ fixes. Four days later the reports have not stopped: on the official Report a Problem thread, players posted on Aug 22 and Aug 24 that their settings look saved but do not actually apply until you toggle one off and back on, and Team17 support replied on Aug 23 that "persistent issues with video settings and keybinds in the full game" had been added to their report. So: partly fixed, still open, still acknowledged. Below is exactly what 1.2 shipped, what is still being reported, and the two workarounds with real evidence behind them.

The five launch keybind bugs Team17 confirmed on Aug 12 — and where Patch 1.2 left them:
  • Gunner Fire / Gunner Alt Fire bindings resetting after leaving the Options menu — fixed in 1.2. Changelog: "Gunner Fire and Gunner Alt Fire keyboard bindings no longer reset after leaving the Options menu."
  • Tac-Map rebinds not reflected inside the map — fixed in 1.2. Changelog: "Custom Tactical Map keybindings are now correctly reflected within the map."
  • A key assigned to a new action not being removed from its old action (double-binding) — fixed in 1.2. Changelog: "Assigning a key to a new action now correctly removes it from its previous action."
  • VOIP channels not working when bound to mouse buttons — not in the 1.2 changelog. No official word either way.
  • Losing keyboard input entirely right after spawning — not in the 1.2 changelog. No official word either way.
The broader "everything resets when I re-enter the in-game menu" complaint from beta was never one of these five. Patch 1.2's highlights do name "Settings not saving correctly", which is the closest official match, but the changelog does not spell out which save path that covers.
Still being reported after Patch 1.2 (checked Aug 25):
  • Settings that save but do not apply. Two players on the official Report a Problem thread, Aug 22 and Aug 24: the menu shows the settings you chose, but the game runs as if it did not load them until you change one value away and back. Team17 support replied on Aug 23 that it had been passed to the team.
  • Mouse wheel still cannot be rebound. One player reports on the Patch 1.2 announcement thread that wheel up / wheel down stay locked to next / previous weapon. Single report, not officially confirmed.
  • What has gone quiet: no new "keybinds keep resetting" thread has appeared on the game's subreddit since Aug 19, two days before the patch. That is an absence of complaints, not proof of a fix.
Patch 1.3 is aimed at "next week" as of the Aug 21 post. The issues Team17 listed as targets for it contain no keybind items.

What was confirmed broken before Patch 1.2

  • Keybinds reset when you re-enter the in-game menu. "You save it, go back in game, and it resets. Even deleting keybinds and getting back in game resets them back" — "Keybinds keep reseting" report thread. One tester pinned the trigger precisely: binds reset "when exiting and entering the ingame menu", not when switching tabs (early-testing feedback thread).
  • Team17 knows. Official support reply, June 2: "we've had the issue with keybinds not saving correctly reported to us already" (support thread).
  • Still present in the July playtest build: mouse-wheel rebinds wouldn't save on Jul 29.
  • Non-QWERTY keyboards (AZERTY etc.) have an extra layer: binds display as the wrong keys and fail to save (AZERTY thread).

What actually helps (evidence-backed only)

  1. Rebind from the main menu, before joining a server. The observed reset trigger is the in-game settings menu; beta players kept binds longer doing everything from the title screen. Close and reopen settings once to confirm it stuck.
  2. Check your config isn't read-only. The popular 60 Hz-unlock fix tells you to set GameUserSettings.ini to read-only — which then silently blocks every settings save. Its own author warns: rebind first, set read-only last (performance thread). If you applied that trick, untick read-only before blaming the game.
  3. Don't hunt for a keybinds file to edit. The config folder is %LOCALAPPDATA%\HLLVietnam\Saved\Config\Windows, but it only holds GameUserSettings.ini (graphics/refresh). Testers found keybinds live in a non-editable .sav file — "Game does not use the typical UE config structure" — so HLL1-era advice about editing binds in the ini does not apply here.
  4. Add your report to the Report a Problem forum — support is actively collecting cases.
